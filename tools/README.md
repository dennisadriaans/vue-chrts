# tools/

Release tooling for this monorepo. Zero dependencies — plain Node, run from the
repo root.

```bash
pnpm release                  # pick a package, walk the release
pnpm release:dry              # same prompts, writes nothing
pnpm release:vue              # skip the picker (vue-chrts)
pnpm release:nuxt             # nuxt-charts (v3)
pnpm release:nuxt-legacy      # nuxt-charts-legacy
pnpm test:release             # unit tests for the tool itself
```

## `release.mjs`

Releases **one package per run**. Everything lives in a single git repository
(`dennisadriaans/vue-chrts`), so a release is scoped by its tag:

```
vue-chrts@2.2.2
nuxt-charts@3.0.0-beta.3
nuxt-charts-legacy@2.2.2
```

Flags:

| Flag | Effect |
| --- | --- |
| `--package <name>` | Skip the picker (`vue-chrts`, `nuxt-charts`, `nuxt-charts-legacy`) |
| `--bump <kind>` | `patch` · `minor` · `major` · `prerelease-beta` · `prerelease-rc` |
| `--version <x.y.z>` | An explicit version, overriding `--bump` |
| `--notes <source>` | `commits` · `unreleased` · `fragments` · `none` |
| `--dry-run` | Walks every prompt, writes/commits/pushes/publishes nothing |
| `--skip-verify` | Skips typecheck · test · build |
| `--no-push` | Commits and tags locally, pushes nothing (implies `--no-npm`) |
| `--no-npm` | Everything except the registry |
| `--all-commits` | Do not filter change detection to the package directory |
| `--yes` | Answer prompts with their defaults (required without a TTY) |

### What it does, in order

1. **Preflight** — git repo, `origin` really is this repo, branch, clean tree, in
   sync with origin, no tracked `.env*`, LICENSE present and free of template
   placeholders, `gh` auth, npm auth.
2. **Package** — pick one of `packages/*`; then its README/CHANGELOG/LICENSE, its
   npm-facing manifest fields (`description`, `license`, `repository`, …), and
   whether its workspace dependencies are published. pnpm rewrites `workspace:*`
   to a concrete version while packing, so releasing `nuxt-charts-legacy` before
   the `vue-chrts` version it points at would ship an uninstallable tarball.
3. **Change detection** — commits since the package's newest tag, filtered to its
   directory. Legacy flat `vX.Y.Z` tags still count as vue-chrts releases
   (`LEGACY_TAG_GLOBS` in `config.mjs`).
4. **Version** — shows all three sources that can disagree (newest git tag, the
   registry, `package.json`) and bumps from the highest, so an aborted release
   never burns a number twice. A version already on npm is rejected outright.
5. **Release notes** — built from conventional commits (grouped into Features /
   Bug Fixes / Performance / breaking changes, with commit and issue links),
   from a hand-written `## Unreleased` section, from `changelog.d/` fragments, or
   from an empty draft — then editable in `$EDITOR`. Commits the notes leave out
   (`chore:`, `ci:`, untyped subjects) are listed before the prompt.
6. **Verification** — `turbo run typecheck · test · build --filter=<package>`.
   turbo skips a task the package does not define and builds its workspace
   dependencies first. Note what `build` means per package: for `vue-chrts` it is
   the published `dist/`, for the two Nuxt modules it is the playground app —
   the module itself is built by `prepack` during publish.
7. **Commit + annotated tag** — `chore(release): <name>@<version>`.
8. **Push** — branch + tag, behind an explicit confirmation.
9. **npm** — `pnpm publish` (not `npm publish`: only pnpm rewrites `workspace:*`)
   with the dist-tag derived from the version — `latest` for a stable release,
   `beta`/`rc` for a prerelease. Publication is verified against the registry
   afterwards.
10. **GitHub Release** — `gh release create` with the same notes, `--prerelease`
    for beta/rc versions.

Every network- or history-changing step is a separate confirmation, and aborting
before step 7 leaves the tree untouched.

### CHANGELOG format

The release section matches what `commit-and-tag-version` used to write, so a
package's history stays consistent:

```markdown
## [2.2.2](https://github.com/dennisadriaans/vue-chrts/compare/v2.2.0...vue-chrts@2.2.2) (2026-08-13)

### Bug Fixes

* **TopoJSONMap:** emit mouseenter/mouseleave ([#135](…)) ([5272de6](…))
```

A `## Unreleased` heading is optional. Files that never had one (all of them, as
generated by `commit-and-tag-version`) get the new section inserted above the
newest release instead.

### Modules

| File | Responsibility |
| --- | --- |
| `release/config.mjs` | paths, repo constants, tag scheme, verify + required-file lists |
| `release/workspace.mjs` | package discovery, workspace dependency graph |
| `release/ui.mjs` | prompts, colours, `$EDITOR` |
| `release/exec.mjs` | spawn helpers |
| `release/version.mjs` | semver parse/compare/bump, npm dist-tag derivation |
| `release/preflight.mjs` | the checks in steps 1–2 |
| `release/detect-changes.mjs` | tags and commits since a package's last release |
| `release/changelog.mjs` | conventional-commit grouping, CHANGELOG.md assembly |
| `release/publish.mjs` | version write, verify, commit, tag, push, GitHub Release |
| `release/npm.mjs` | registry queries and `pnpm publish` |
| `release/release.test.mjs` | unit tests (`node --test`) |
